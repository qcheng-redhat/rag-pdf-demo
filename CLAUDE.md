# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `pip install -e .` — install package in editable mode
- `pdf-rag index --pdf-dir <dir>` — index PDFs into Chroma vector DB
- `pdf-rag index --pdf-dir <dir> --embed-backend local` — index with local embeddings
- `pdf-rag index --pdf-dir <dir> --reset` — re-index from scratch
- `pdf-rag ask "your question"` — retrieve context and answer
- `pdf-rag ask "question" --top-k 10` — adjust number of retrieved chunks
- `python -m pdf_rag ...` — run as module (equivalent to `pdf-rag`)
- No tests exist yet (use `pytest` when added)

## Env vars

| Variable | Purpose | Default |
|---|---|---|
| `PDF_RAG_EMBED_BACKEND` | Embedding backend: `openai` or `local` | `openai` |
| `PDF_RAG_EMBED_MODEL` | OpenAI embedding model | `text-embedding-3-small` |
| `PDF_RAG_LOCAL_EMBED_MODEL` | Local embedding model | `sentence-transformers/all-MiniLM-L6-v2` |
| `PDF_RAG_LOCAL_EMBED_BATCH` | Local embed batch size | `32` |
| `PDF_RAG_CHAT_MODEL` | Chat model for `ask` | `gpt-4o-mini` |
| `PDF_RAG_CHUNK_SIZE` | Text chunk size (chars) | `1200` |
| `PDF_RAG_CHUNK_OVERLAP` | Chunk overlap (chars) | `200` |
| `OPENAI_API_KEY` | Default API key | — |
| `PDF_RAG_EMBEDDINGS_API_KEY` / `PDF_RAG_EMBEDDINGS_BASE_URL` | Override embedding API key/host | falls back to `OPENAI_*` |
| `PDF_RAG_CHAT_API_KEY` / `PDF_RAG_CHAT_BASE_URL` | Override chat API key/host | falls back to `OPENAI_*` |
| `PDF_RAG_DB` | Chroma persist directory | `./.pdf_rag_chroma` |

## Architecture

The package (`src/pdf_rag/`) has no sub-packages, all modules are siblings:

- **`config.py`** — Centralised env-var reading: persist directory, embedding backend selection, model names, chunking params, batch sizes.
- **`ingest.py`** — PDF text extraction via `pypdf.PdfReader`. `iter_pdf_documents()` yields `(Path, list[(page_num, text)])` for all `*.pdf` in a directory.
- **`chunking.py`** — sliding-window text chunker (character-level, not token-aware). `chunk_text(text)` returns `list[str]` with default 1200-char chunks and 200-char overlap.
- **`embedding.py`** — Embedding dispatch (OpenAI API or local sentence-transformers). `embed_texts()` handles batching and backend routing; `openai_embed_client()` builds an OpenAI-compatible client. Local model is lazily loaded as a module-level singleton.
- **`store.py`** — ChromaDB `PersistentClient` wrapper. `get_collection()` returns a Chroma collection in cosine space from the given persist dir.
- **`rag.py`** — Indexing orchestration: `index_folder()` reads PDFs, chunks, embeds, and writes to Chroma. (Ask/chat logic lives in `chat.py`.)
- **`chat.py`** — Question answering: `ask()` embeds the question, queries Chroma for `top_k` similar chunks, then calls an OpenAI-compatible chat API to answer with source citations.
- **`cli.py`** — `argparse` CLI with `index` and `ask` subcommands. The `--embed-backend` flag must match between indexing and querying since embeddings are computed client-side and stored in Chroma.

## Troubleshooting

- **`[Errno 101] Network is unreachable` with `--embed-backend local`** — the sentence-transformers model downloads from Hugging Face on first use. If your environment blocks Hugging Face, set `HF_ENDPOINT=https://hf-mirror.com` to use the CDN mirror. Alternatively, pre-download the model on a machine with internet (it caches to `~/.cache/huggingface/`) and copy the cache to the target machine.

## Key constraints

- The `--embed-backend` choice must match between `index` and `ask` (embedding vectors live in Chroma, not generated by Chroma's built-in embedding function).
- Chroma persist directory is not portable between embedding backends — reset with `--reset` to switch.
- Embeddings are computed client-side in batch (default 64), then stored via `col.add(embeddings=...)`. This is the reverse of Chroma's typical usage where it computes embeddings internally from raw text.
